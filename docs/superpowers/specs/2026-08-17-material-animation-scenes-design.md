# AISpur 素材专属动画场景 — 设计总案

> 日期：2026-08-17
> 状态：**待审批**
> 范围：52 个素材的专属爆裂动画系统性重做

---

## 一、问题诊断（基于逐素材静态分析，非推测）

排查 `src/overlay/material-visual.ts`（2650 行，52 个 `case` 全部独立，无共享/撞车）后，真实结论：

| 现状 | 数据 |
|---|---|
| 有「叙事」的素材（精灵轨迹 ≥3 段 且 粒子 ≥3 层） | **仅 9 个**：whip、classic、rocket、flame、meteor、skull、crown、sword、lightning |
| 单层粒子素材 | **约 43 个**（粒子 10–45，仅一层） |
| 精灵轨迹仅 2 段（蓄力→飞走，无起承转合） | **约 40 个** |
| 最单薄的素材 | horn(10)、star(10)、trident(12)、blowgun(12)、slingshot(15)、chain(15)、football(15)、dragonfly(15)、tessen(16)、flail(18) —— 几乎等于一个点爆开 |
| 色相挤在同一暖区 | hammer(30)、scepter(45)、boomerang(20)、slingshot(30)、drum(35)、bell(45)、horn(40)、football(35)、guitar(30)、axe(15)、scythe(0)、boxing(0)、chakram(45) … 一片橙/红/金黄，**肉眼分不出谁是谁** |
| 轨迹不体现身份 | 大量 sprite 只是「缩放 + 向右/向上飞 + 淡出」，弓箭、锁链、号角、竖琴的动画彼此无差异 |

**一句话诊断**：大多数素材是「**有不同颜色的简单迸裂**」，而非「有专属叙事身份的动画」。这正是你说的「太简单、没有关联性」。

---

## 二、改造方向（已与用户确认，三轨并行）

1. **精灵与素材语义关联** — 每枚素材的动画叙事（轨迹）与身份强绑定：弓箭→抛物线齐射、锁链→缠绕拖拽、号角→声波扩散、竖琴→音符（♪）跳跃。
2. **色相与素材身份关联** — 每枚素材一个**专属主题色**（查表取代 + 收敛随机色）：火焰=红橙、水=深蓝、闪电=亮黄、骷髅=灰白绿、雪花=冰蓝。消除一片暖橙。
3. **动效与鞭子运动物理绑定** — crack 瞬间把鞭梢**实时速度向量**传给爆裂：方向=鞭梢运动方向、强度/粒子量=速度大小、快甩=剧烈、慢抖=温和。

---

## 三、架构改动（为实现物理绑定）

### 3.1 数据流（4 处改动）

```
SwingDetector.push() ──► { cracked, vx, vy, peakSpeed }
        │                      ↑ 现在只返回 boolean，需扩展
        ▼
main.ts  triggerCrack(x, y, {vx, vy, speed})        // 速度向量传进爆裂
        ▼
ImageMaterial.startCrack(x, y, vel)                 // 签名扩展
        ├── style.emit(cx, cy, vel)      // 方向=速度向量；粒子量∝speed
        └── style.sprite(t, vel)         // 精灵飞向=速度向量；幅度∝speed
```

### 3.2 各文件改动

| 文件 | 改动 |
|---|---|
| `src/overlay/swing.ts` | `push()` 改为返回 `{ cracked, vx, vy, peakSpeed }`（在 snap 判定帧捕获速度向量与峰值） |
| `src/overlay/main.ts` | `triggerCrack(x,y,vel)` 把 vel 传给 `startCrack` |
| `src/overlay/material-visual.ts` | `CrackStyle` 接口扩为 `sprite(t, vel)`、`emit(cx,cy,vel)`；新增向量归一化 helper + 强度映射 |
| `src/overlay/material-visual.ts` | 新增 `MATERIAL_HUE: Record<id, number>` 专属色相查表，`.hue` 查表取，不依赖随机 |

### 3.3 兼容性
- 未带 vel 的调用（测试/兜底）回退 `{vx:1, vy:0, speed:base}` → 契约测试不破。
- `swing.test.ts` 同步更新返回值断言。

## 四、专属主题色规范

**原则**：色相与该素材「本来就是什么」挂钩。冷色冷、暖色暖、金属灰白、自然青绿。

| 语义族 | 色相范围 | 素材 |
|---|---|---|
| 火焰/爆炸/热血 | 8–45（红→橙→黄） | flame/bomb/volcano/meteor/boxing/axe/sword 等 |
| 金属冷刃 | 195–225（亮银蓝）+ 高亮 | sword/dagger/spear/axe/halberd/shield/chakram/chain |
| 水/冰/风/天象 | 170–220（青→蓝→冰白） | water/tornado/wind/snow/rain/lightning 等 |
| 植物/生命 | 90–140（绿） | bamboo/lotus/dragonfly/guitar(木) |
| 玄学/神圣 | 250–330（紫、粉、金） | amulet/crystal/crown/scepter/lotus |
| 乐器铜木 | 30–50（黄铜、原木） | horn/bell/harp/flute 等 |

> 每素材精确色相见第五节「专属色」字段。

## 六、冲击力增强（用户追加需求）

除前三节的个性化外，用户明确要求**整体扩大显示范围、放大动画尺寸、突出冲击力**。
overlay 为全屏透明窗口，放大不超出画布，技术安全。

### 6.1 全局尺寸参数（material-visual.ts 顶部常量）

| 常量 | 现值 | 目标 | 说明 |
|---|---|---|---|
| `CURSOR_MAX_PX` | 56 | **96** | 精灵基座尺寸（光标跟随 + 爆裂起点）。爆裂时叠加 scale，峰值更大 |
| `CRACK_MS` | 1200 | 1200 | 时长不变；冲击力靠幅度与密度而非时长 |
| 单素材粒子上限 | 120 | **180** | 冲击力靠量；批量绘制已优化，180 粒子仍 ≥60fps |

### 6.2 爆发要「更早更猛，砸得更大」

- **scale 峰值**：各素材爆裂峰值从 ~2.8 提到 **~3.8**（精灵峰面约 96×3.8≈365px，近半屏，更有「炸满视野」的冲击感）。
- **爆发前置**：第一段爆发（t<0.2）的 scale 增量拉大、位移加速，让「炸开」瞬间有劲，而不是缓慢散开。
- **位移范围**：各素材 `emit` 的粒子速度/位移系数整体 ×1.6，粒子飞得更远、占满更多屏幕；末端加上限防止飞出可视区。

### 6.3 冲击特效叠加

每个素材爆裂在核心叙事**之上固定叠加**两层冲击辅助（不改变素材专属叙事）：
- **冲击光环**：爆心一道快速扩散的光环（streak 圆环），起爆瞬间最亮。
- **中心闪光**：起爆 0–0.15 帧一记白热亮斑（dot 高密度 + 高 alpha），先亮后散，制造「爆」的爆点。

> 这两层是**横切全局**的增强层，加到每个 `emit` 结果里，不替代素材专属粒子；保证单素材总量 ≤180。

### 6.4 冲击力的验收口径

冲击力不以「更大」为唯一标准，以**对比强弱**为准：
- 甩得快 → 冲击光环更亮更远、闪光更猛（沿物理绑定）。
- 甩得慢 → 冲击温和、光圈收敛。

## 八、验收标准

1. **差异化**：任意两素材爆开肉眼可区分（轨迹 + 色相均不同）。
2. **语义**：能猜出「这是谁的动画」（弓箭会射箭、号角出音波）。
3. **色相**：消灭暖橙一片；雪花不再橙色、闪电不再蓝色。
4. **物理**：快甩→大爆裂、慢抖→轻迸散，方向跟手。
5. **性能**：单素材粒子 ≤180，≥60fps（CRACK_MS 保持 1200）。
6. **测试**：全部 Vitest + cargo test 绿；新增物理绑定契约测试。
7. **结构**：色相查表集中化，`.hue` 不再随机。
